# 选段与粗剪规则（母带 1.2× 时间域）

从原 `livestream-clip-pipeline` 的 Step 1/1a/1b/1c/1d/2b 蒸馏而来，全部改成按**母带时间**（=成片时间）执行。
标准本身（选题口味、条数、命名、废句分工）在 `../selection-profile.md`，本文件只讲怎么操作与踩过什么坑。

## 1. 候选怎么找出来

停顿切块只用来**圈范围**，绝不是刀口：

```bash
python scripts/select_helper.py blocks --srt master.srt --gap 4 --min-dur 180 --target 300
```

相邻字幕间隔 >4s 处断块，量出 ≥3 分钟的块；`OK` 标记表示已成片 ≥5 分钟。
连麦/对话段几乎不停顿，块会很长；念公屏提问的独白段停顿多，块会碎——碎不等于没内容，
要用 `show` 读一遍再判。

**刀口由语义决定**：落点必须找话题转折句（`然后X同学 / 下一个问题 / 再说Y / 大二的…`），
往前收到该话题真正的第一句，往后收到它自己收口的那句（"所以按我说的做就 ok 了""那白费啊"是内容，不能切掉）。

主播在话题**内部**也会换气、看公屏、停好几秒，声学边界和语义边界经常差好几条字幕。

## 2. 主播点名要剪的段落，一律交付

直播里直接对剪辑师喊话的句子：「这一段那个剪辑，帮我剪出来啊」「剪辑到时候帮我剪下来啊，打个标记」
「我回头把这个剪成切片」——这类段落必须逐条交付，**不受时长档、条数上限、不重叠三条约束**，
那是素材方自己的选题意图，优先级高于选段标准。

```bash
python scripts/select_helper.py marks --srt master.srt
```

- 开工先全文扫一遍，**不要找到第一处就停**：一场通常有两三处。
- 排除噪声命中：`标准 / 目标 / 评判标准 / 剪指甲 / 做剪辑的 / 给作业打标记 / 进行标记`（点评规则里的"标记"不是点名要剪）；
  要连前后 3 条读完再判。
- **点名句 ≠ 段落起点。** 他说"刚才那段"时，所指内容往往在几十秒到几分钟之前，中间可能还被打断过：
  往前找到该话题真正的第一句，跳过"起了个头又被提问打断、随后重讲一遍"的废起句（取重讲那次）；
  往后收到该话题自己的收口句。
- 点名段落内部的脏话照常用多区间挖掉；再短也交付（几十秒也算一条）。
- 交付报表里逐条写明：点名原话 + 字幕序号 + 时间码，一眼能核对有没有漏。
- 最后一道闸：`marks` 命中数 与 成品里点名段文件数 必须相等，不等就是漏了；
  宁可写明"第 N 处未交付及原因"，也不要默默少交。

## 3. 七项准入（每条必过，过不了就改边界或弃用）

1. **起点句是本话题第一句**。`show --edge` 打印起点前 2 句确认；如果前一句才是
   "我回答一个问题啊""我跟你们说一个事啊就是"这种带钩子的引入句，起点必须前移把它含进来——
   引入句是给观众的预期，不是废句。区分标准：这句有没有态度/悬念，有就留，纯程序性报幕才删。
2. **起点句、标题、内容概括说同一件事**。三者互查：概括描述的是区间**中后段** → 起点偏早，
   前面属于上一个提问；标题写的事在起点句里完全看不出来 → 同样判不过。
3. **终点句语法完整且是收口句**（总结、金句、态度爆发、反问收尾都行），
   绝不能停在半句或单字语气条（"嗯""啊""对"）上；终点后 2 句要读一遍。
4. **成片时长达标**。母带已是 1.2×，`blocks` 量的跨度**就是成片时长**，不再乘 0.7 折算；
   ≥5:00 优先，退档 3–5:00 必须是单一话题完整起止。
5. **标题里有一个能逐字搜到的锚点**（数字、公司名、专业名、原话短语），锚点位置在全片前 45% 内：
   ```bash
   python scripts/select_helper.py anchor --srt master.srt --from 900 --to 1300 --title "八千的offer我劝他别去"
   ```
   反例：标题写"校招20万起"而"20万"在全片 55% 处 → 前段选错了。
6. **与其他已选片、与点名段落不重叠**（点名段优先占位）。
7. **段内脏话/敏感词已定位**：
   ```bash
   python scripts/select_helper.py dirty --srt master.srt --from 900 --to 1300
   ```
   逐条决定"整条挖掉"还是"弃用该段"。

自己新造的边界（拆分、合并、收紧首尾）要和别人给的候选走同一道核验。
经验教训：2026-10-16 一场 11 条里 4 条栽在前四项——**形式核验（半句、时间码）代替不了语义核验（切题）**；
出现过"上半句在 A 片、下半句在 B 片"的情况。

## 4. 粗剪：整条字幕为单位挖废句

写进 `clips.tsv`（同名多行 = 一条片子的多个保留段），由 `plan_from_master.py` 落成保留区间：

- 纯报幕式开场（「嗯看个私信啊」「我念一下私信」「先说一个问题啊」）→ 删，从正文第一句起；
- 问候寒暄（「老师好哎家长好」）→ 删；
- 自我重复提示（「这个我也讲过很多次」「我之前说过这个事」）→ 删；
- 与主线无关的旁支一句带过 → 整块删；
- 口吃重复起句：同一句重说两遍删前一次；
- 同义叠用且能整条定位的：「现在目前」→「目前」。

**不归粗剪**（留给精剪/用户在剪映手工）：句子中间的单个语气词虚词（不要为它们开刀）、改字不改时轴的活
（数字一律阿拉伯、千分位）。

端点永远取**相邻保留条**的时间码，不要拿被删条目的时间码当端点——那会把它的头或尾留在片子里；
相邻字幕首尾相接时尤其容易踩。

粗剪是**粗**的：宁可留一点给精剪，也不要为抠一个词把时间轴切碎——切得越碎接缝越多，精剪反而越难接。
拿不准的条目留着，在报表里标"待精剪定"。

## 5. 长转录通读交给子 agent 的规矩

- 要它给**字幕序号**，时间码/跨度/时长全部由主线用脚本按序号回查——子 agent 的时长算术会错
  （出现过把 9:08 的段标成 5:4、写出 3440 秒这种乱数）。
- 要它同时给"一句话内容概括"，主线用概括**反查起点**：概括讲的是中后段内容，就说明起点偏早。
- 它标"可挖掉的岔口/推销段"必须回读原文再决定——出现过它把整段里最有戏的自曝当岔口建议删掉。
- 它给的脏话行号也要逐条核对，实测有报错行位。
- 主线必须自己用 `show --edge` 把每条候选首尾各 3 条读一遍，并跑 `audit_bounds.py`。

## 6. 交付前边界审计

```bash
python scripts/select_helper.py dump --srt master.srt --out cues.tsv
python scripts/audit_bounds.py --dump cues.tsv --manifest clips.tsv[,clips_返修.tsv...]
```

它摊出每条的「前 2 句 / 起点句 / 终点句 / 后 2 句」，标 START-MIDSENTENCE / END-CLIPPED / TITLE-LATE。
**四行必须逐条人工读**——启发式只能兜住这三类，切题与否靠人眼。返修过的片子把新旧清单一起传，同名以靠后的为准。

## 7. 停顿扫描的 off-by-one

间隔出现在 cue N 与 N+1 之间时，新块起点是 **N+1** 不是 N。`select_helper.py blocks` 已按 N+1 处理。
