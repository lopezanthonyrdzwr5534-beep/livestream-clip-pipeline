# Livestream Clip Pipeline · 直播切片流水线

**English** · [中文](#中文版)

An **Agent Skill** that turns a livestream or podcast recording and its SRT subtitles into
**editable drafts inside your NLE project**, in two passes:

**Pass 1 — the agent delivers clean, packaged, subtitle-free drafts**

1. **Select** — read the transcript and pick high-value continuous ranges *by cue index*. Your
   criteria are captured once via a 3-question interview, persisted to `selection-profile.md`,
   and reused on every later run (revise anytime).
2. **Clean** — delete whole junk cues (greetings, restated openings, follow pleas, digressions)
   from the text, before any cutting happens.
3. **Cut & trim** — FFmpeg extracts each kept range by SRT timestamp (frame-accurate
   input-seek + re-encode, HEVC/H.264 both fine); auto-editor removes breaths and silence.
   The material stays at **1.0×**.
4. **Package & install** — each clip becomes a single-segment draft on a fixed vertical
   template (1080×1920, colour 0.8, top-strip blur, two title lines, **no subtitle track**),
   appended to the source project as timeline 02+. The playback speed (commonly **1.2×**)
   lives only in the draft, so you can dial it back inside the NLE.

**Pass 2 — after you recognise subtitles in the NLE**

5. **Proofread** — typos, domain terms, pronouns, numbers written back into words; merge short
   pauses, de-duplicate stutters, split long lines, zero gaps between cues. Only the subtitle
   track is rebuilt.
6. **Titles** — finalised from the corrected subtitles as a *distillation* with a hook, every
   number and fact greppable back to a cue. Delivered as text; never written back into a
   timeline you have already hand-edited.
7. **Effects** — sparse sound effects / visual effects placed by what each line *does*
   (0.3–1.2 per minute), then verified against the resources actually on disk.

A standalone one-pass script (`scripts/pipeline.py`, cut + trim straight to finished MP4) is
still included for workflows that do not use an NLE.

## Requirements

- Python 3 with `jieba` (the subtitle splitter degrades without it)
- [auto-editor](https://github.com/WyattBlue/auto-editor) — `python -m pip install auto-editor`
- [FFmpeg](https://github.com/FFmpeg/FFmpeg) — `winget install Gyan.FFmpeg` (Windows) / `brew install ffmpeg` (macOS)
- For the draft workflow: a JianYing/CapCut-style NLE project, and `jy-draftc` plus the NLE's
  `videoeditor.dll` directory for decrypt/encrypt (`--jy-dir`)

The scripts auto-locate ffmpeg and auto-editor (PATH, pip user Scripts, winget package dirs);
override with `--ae`.

## Install as an agent skill

Copy this folder into the skills directory of any assistant that supports SKILL.md-style
skills (e.g. `~/.claude/skills/`). Then say: *"run the livestream clip pipeline on this SRT and
this recording."* First use asks 3 questions and writes your profile; later runs apply it
directly.

Two files are **not** shipped and are created locally:

- `selection-profile.md` — your personal criteria (gitignored).
- `assets/fx_library.json` — generated by `scripts/build_fx_library.py` from your own
  timelines; it records absolute cache paths, so it is machine-specific (gitignored).

## Standalone script usage

Works without any AI assistant, once you have a manifest:

```bash
python scripts/pipeline.py --src REC.mp4 --manifest clips.tsv --outdir OUT/ --dry-run
```

`clips.tsv` — one range per line: `start<TAB>end<TAB>name`; timestamps in SRT form
(`hh:mm:ss,ms` or `hh:mm:ss.ms`); `#` lines ignored. Lines sharing the same `name` are cut and
concatenated into one clip (multi-range keep-cut for refined editing).
Tuning: `--margin 0.4s` (cuts too choppy → raise), `--edit "audio:threshold=0.005"` (silence
left → raise), `--fps 30` (keep the default; only raise it if you truly need native frame rate
and will check for black frames), `--keep-raw` (debug), `--dry-run`.

The two-pass chain uses `select_helper.py` → `make_manifest.py` → `pipeline_mp4.py` →
`build_draft.py` → `install_timeline.py`, then `rework_subtitles.py` → `subtitle_audit.py` →
`build_fx_library.py` / `check_resources.py` / `restore_fx.py`. See SKILL.md for each step.

## Design notes (field-tested)

- Verify SRT ↔ video timeline alignment before cutting (SRT max timestamp ≈ video duration,
  same origin, no wrapped/backwards timecodes); misalignment cuts the wrong scene silently.
- A clip counts as trimmed only if `final < raw`; report honestly when a span holds no
  detectable silence. Flag >30% removal per clip for a spot-check so speech never gets chopped.
- For transcripts over ~2h, let a sub-task read the whole thing and return only the ranked
  table — **cue indices only**; recompute timestamps and spans yourself, and re-read every
  "this is a digression, drop it" suggestion against the source.
- **Budget duration by which pipeline you run.** One-pass to finished MP4: `final ≈ span × 0.7`
  (measured 0.69–0.84 across three streams; phone-in dialogue barely shrinks, monologue that
  keeps reading chat shrinks a lot). Two-pass with 1.2× in the draft:
  `timeline ≈ span × 0.6` (breaths ≈ −28%, then 1.2× ≈ −17%) — for a ≥5-minute clip select a
  span of ≥8:30.
- **Silence is not a topic boundary.** Gaps >4s narrow candidate ranges only; the cut must land
  on a topic-turn line. Cutting on a pause has split one sentence across two clips. The default
  fix for a dirty boundary is to **merge it back into the neighbouring topic**, not to drop it.
- **Seven admission checks per candidate** before it enters the manifest: the opening cue is
  the topic's first line; opening cue, title and summary describe the same thing; the closing
  cue is a complete punchline; the span fits the duration band after budgeting; the title's
  hook is really argued in the clip and its evidence lands in the first 45%; no overlap with
  selected or host-flagged segments; profanity inside the span located and handled.
  `make_manifest.py` enforces two of them as hard gates (`[SHORT]`, `[CONTINUATION]`) and exits
  1 rather than letting a bad range through; `--allow-short` / `--allow-continuation` are human
  sign-offs, not tuning knobs.
- **The host's on-air request has two opposite meanings.** "Editor, cut this part out for me" /
  "mark this" means *deliver it unconditionally* (exempt from length, count and overlap rules).
  "Cut this bit" / "don't air this" means *excise the whole block*. Read three cues around every
  hit before deciding, and enumerate all hits first — a stream usually has two or three. The
  request line is rarely where the segment starts.
- **Speed lives in exactly one place.** Material 1.0× + draft `speed: 1.2`, or material 1.2× +
  draft `speed: 1.0` — never both. The NLE reads speed from the `speeds` material in a segment's
  `extra_material_refs`, not from `seg.speed`; copying the template's own 1.2× speed material
  makes it rewrite the source range as `target × 1.2`, which drifts the waveform and freezes the
  last frame while audio continues.
- **`path_exists` in the effect library is a snapshot, not live state.** The NLE cleans up
  unused packages, so an effect can go silently mute. Re-run `check_resources.py` against the
  written-back timeline after placing events, and fix a missing asset by swapping it on the same
  segment — never by re-running the placement script. `restore_fx.py` can re-download a missing
  package offline from the NLE's own resource database (`rp.db` → URL → MD5 check → extract),
  leaving timing and placement untouched; assets with no record there are delisted and must be
  replaced by hand.
- **Black frames** (each one cost a re-render before the script handled it): cuts are normalized
  to `--fps 30` because auto-editor v29 inserts black frames at its cut points on 60fps sources;
  a preroll seek absorbs the black head that long-GOP HEVC/TS recordings show after a cold seek;
  and every finished clip goes through a `blackdetect=d=0.02` pass that trims away black lying
  within 1s of either edge.
- `scripts/audit_bounds.py` (read-only) prints each clip's two preceding / opening / closing /
  two following subtitle lines and flags `START-MIDSENTENCE`, `END-CLIPPED`, `TITLE-LATE`. Run it
  before delivery. It exists because formal checks (half sentences, timecodes, black frames)
  kept passing while the selection itself was wrong.
- A mask can only be verified **visually inside the NLE**. "JSON validates" and "the export has
  audio" prove nothing about it; a missing mask package turns a top-strip blur into a
  full-screen blur.

## 中文版

**直播切片流水线**：一个 Agent Skill，把「直播/播客录屏 + SRT 字幕」做成**装进你自己工程里的可编辑草稿**，分两道。

**第一道（助手做）：交付干净、包装好、没有字幕的草稿**

1. **选段** — 通读字幕，**按字幕序号**挑高价值连续区间。首次只回答 3 个问题（内容领域 / 好切片标准与明确不要什么 / 单片时长与条数），标准写入 `selection-profile.md`，之后每次直接沿用，随时可改。
2. **删废句** — 在截段之前用文本定下要整条删掉的句子（问候、重复起句、求关注、旁支）。
3. **截段 + 剪气口** — FFmpeg 按 SRT 时间码帧精确截取（输入定位 + 重编码，兼容 HEVC/H.264），auto-editor 去除停顿与静音。**素材保持 1.0×**。
4. **包装 + 安装** — 每条做成单段草稿，套固定竖屏模板（1080×1920、调色 0.8、顶部模糊、两条标题、**不带字幕轨**），追加为源工程的时间线 02+。播放速度（常用 **1.2×**）只写在草稿里，你能在剪映里调回去。

**第二道（你在剪映里识别完字幕之后）**

5. **订正字幕** — 错字/术语/代词/数字写回中文；合并短停顿、去口吃重复、拆长条、相邻条 0 缝。只重建字幕轨。
6. **定标题** — 读完订正后的字幕再提炼爆点，每个数字和事实都要能在字幕里搜到出处。**只交文本**，不写回你手改过的时间线。
7. **加音效/特效** — 按台词功能稀疏投放（每分钟 0.3–1.2 个），放完再对写回的时间线核一遍资源是否真在盘上。

另附可独立运行的一趟式脚本 `scripts/pipeline.py`（截段 + 剪气口直接出成品 MP4），适合不用剪映的流程。

**依赖**：Python 3（带 `jieba`，否则拆条退化）；`python -m pip install auto-editor`；FFmpeg（Windows 推荐 `winget install Gyan.FFmpeg`）。走草稿流程还需要剪映工程、`jy-draftc` 以及含 `videoeditor.dll` 的目录（`--jy-dir`）。脚本会自动在 PATH、pip 用户目录、winget 包目录中定位工具。

**安装**：把本目录整体拷入你所用 AI 助手的技能目录（任何支持 SKILL.md 格式的助手，如 `~/.claude/skills/`），对它说"用直播切片流水线处理这份 SRT 和原片"即可；首次会访谈，之后直接按画像执行。

有两个文件**不随仓库发布**、在本机生成：`selection-profile.md`（你的个人标准）与 `assets/fx_library.json`（由 `build_fx_library.py` 从你自己的时间线生成，记的是本机绝对路径）。两者都在 .gitignore 里。

**脱离助手单独用脚本**（手工写好 manifest 后）：

```bash
python scripts/pipeline.py --src REC.mp4 --manifest clips.tsv --outdir OUT/
```

manifest 为 TSV，每行 `开始<TAB>结束<TAB>输出名`，时间码支持 `hh:mm:ss,ms` 或 `hh:mm:ss.ms`；**同名的多行会各自截取再拼接为一条成片**（精剪保留段用法）。常用参数：`--margin 0.4s`（防剪碎）、`--edit "audio:threshold=0.005"`（多剪）、`--fps 30`（保持默认即可；确需原帧率再改，并自行检查黑帧）、`--keep-raw`（排查）、`--dry-run`（先验）。

两道式链路依次是 `select_helper.py` → `make_manifest.py` → `pipeline_mp4.py` → `build_draft.py` → `install_timeline.py`，再 `rework_subtitles.py` → `subtitle_audit.py` → `build_fx_library.py` / `check_resources.py` / `restore_fx.py`，每一步见 SKILL.md。

**设计约束（实测沉淀）**：

- 开工前必须核验 SRT 与原片时间轴对齐（最大时间戳 ≈ 视频时长、同起点、序号连续无回退）；有些导出是**卷绕**的（文件从时间轴中段开始），要先按时间重排。多段原片先确认 SRT 对应哪一段——错轴会安静地截错场景。
- 成片必须 `剪后 < 截出` 才算剪到东西；相等时如实报告"该段无可剪静音"，不得谎称已剪。剪除比例超过 30% 的单独提示抽看。
- 超长转录（>2 小时）的通读交给子任务，主线只接收排序后的选段表，且**只要字幕序号**：时间码、跨度、时长全部主线自己回查计算（实测它的算术会错）；它标的"可挖掉的岔口"必须回读原文再决定。
- **时长按你跑哪条流水线预算。** 一趟式出成品 MP4：`成片 ≈ 跨度 × 0.7`（三场实测 0.69–0.84，连麦对话几乎不缩，边念公屏边讲的独白掉得多）。两道式、1.2× 放草稿：`时间线 ≈ 跨度 × 0.6`（气口约 −28%，再 1.2× 约 −17%）——要成片 ≥5 分钟，跨度得按 ≥8:30 选。
- **停顿不等于话题转折。** 相邻字幕停顿 >4 秒只用来圈候选，真正下刀必须落在话题转折句上；按停顿切过，出现过一整句的前半在 A 片、后半在 B 片。**边界不干净时的默认动作是回并到相邻话题，不是弃用**；弃用只给整段无价值。
- **候选进清单前过七项准入**：起点句是本话题第一句；起点句·标题·概括三者说同一件事；终点句是完整收口；折算后落在时长档内；标题的爆点这段真讲了、依据出现在前 45%；不与已选段和点名段重叠；段内脏话敏感词已定位并决定删或弃。`make_manifest.py` 把其中两条做成硬闸门（`[SHORT]`／`[CONTINUATION]`），不通过直接退出 1；`--allow-short`／`--allow-continuation` 是人工签字，不是调参旋钮。
- **主播点名有两种相反的意思。**「这段那个剪辑帮我剪出来啊／打个标记」＝**无条件交付**（不受时长档、条数、不重叠约束）；「这段掐掉／别播」＝**整块挖掉**。每个命中都要读前后三条再定性，且先把全场命中列全（一场通常两三处）——点名句本身几乎不是起点。
- **速度只放一处。** 素材 1.0× + 草稿 `speed: 1.2`，或素材 1.2× + 草稿 `speed: 1.0`，**不能既烘又设**。剪映从段子 `extra_material_refs` 里的 `speeds` 素材读速度，不看 `seg.speed`；把模板自带的 1.2× 速度素材一起复制过来，它会把源区间改写成 `target × 1.2`，结果波形漂移、片尾画面卡住而声音继续放。
- **音效库里的 `path_exists` 是快照不是实时状态。** 剪映会清理没用过的素材包，特效可能静悄悄没声。放完事件要对**写回后的时间线**再跑一次 `check_resources.py`；缺包就在同一个段上只换素材，别重跑投放脚本（会把整张事件表再放一遍）。`restore_fx.py` 能按剪映自己的资源库（`rp.db` → 下载地址 → 校验 MD5 → 解回原位）离线补包，时轴和落点一个字不用改；库里查无记录的等于已下架，只能手工换同类。
- **黑帧**（每一条都先踩过坑才写进脚本）：截段统一归一化为 `--fps 30`，因为 auto-editor v29 在 60fps 源上会在自己的剪切点插黑帧；长 GOP 的 HEVC/TS 源冷启动定位会出黑头，用预滚 seek 规避；成片还会跑一遍 `blackdetect=d=0.02`，把落在首尾 1s 内的黑帧就地复剪掉。
- `scripts/audit_bounds.py`（只读）把每条的「前 2 句 / 起点句 / 终点句 / 后 2 句」摊出来，并标 `START-MIDSENTENCE`／`END-CLIPPED`／`TITLE-LATE`。交付前必跑——它存在的原因就是：形式检查全过了，选段照样是错的。
- **蒙版只能在剪映里目视确认。**「JSON 校验通过」「导出有声」都证明不了蒙版正常；蒙版包缺失会让顶部模糊变成全屏模糊。
